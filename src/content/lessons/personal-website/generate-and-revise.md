## The first draft is material to review

Generation is the beginning of the work, not the end. The first draft may be attractive while still containing inaccurate summaries, weak priorities, broken links, generic headings, or layouts that fail on a phone.

Review in layers so you do not polish the wrong content:

1. **Truth:** names, dates, organizations, claims, statistics, skills, and project details.
2. **Message:** whether a visitor can quickly understand who you are and what you want.
3. **Structure:** section order, heading hierarchy, scannability, and calls to action.
4. **Presentation:** typography, spacing, colour, responsive layout, and restrained motion.
5. **Function:** navigation, links, downloads, forms, keyboard use, and mobile controls.

## Ask for one clear change

Instead of “make it better,” identify the problem and desired result. For example:

> The project cards are visually equal, but the first project is my strongest evidence. Make it the featured project with more room for context and contribution. Keep all facts, the colour palette, and the remaining project order unchanged.

Specific requests are easier to review and reverse. If you ask for new copy, a complete redesign, animation, and mobile fixes at once, you may not know which change created a new problem.

## Protect working versions

Save or duplicate a version before large changes. If the builder makes the page worse, return to the last strong version rather than stacking repair prompts on top of a broken direction.

> Describe → Generate → Review → Change one thing → Review again.
